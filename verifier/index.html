Verify a Pearl

Every app in this catalog ships with a Solana on-chain ReleaseEntry attesting its binary. Independent verification needs no trust in this static site — the catalog publishes everything required to re-check the chain yourself.

Trust model

Each Melusina release is signed by a Squads multisig vault (the partner's quorum). The signature lands in a ReleaseEntry program-derived account on Solana mainnet, indexed by MasterNftMint + releaseNonce. The entry pins three hashes: appHash (the .spk content), releaseHash (the canonical signing payload), and the authorSig (ed25519 signature over releaseHash by a quorum member).

This is the only trust root. There are no PGP keys, no detached metadata signatures, no out-of-band approvals — legacy .asc files are explicitly rejected at publish time.

What the catalog publishes per app

Every entry in apps.json carries an attest block. The full RELEASE.json is mirrored at /attest/<appId>/RELEASE.json; the catalog summary is the public index of those fields.

FieldMeaning
schemaAlways melusina-release-v1.
appHashSHA-256 of the .spk bytes. The installer recomputes this and refuses to install on mismatch.
releaseHashSHA-256 of the canonical signing payload (appHash + MasterNftMint + releaseNonce + manifest digest). The signed message.
releaseNonceMonotonic counter per app. Replay-resistance for the ReleaseEntry PDA.
releaseEntryPdaThe Solana account address that holds this release on-chain. Look it up on any explorer.
MasterNftMintThe license NFT that gates this app. Owner = current rights-holder.
licenseSquadsVaultSquads multisig vault PDA whose members co-signed this release.
signedAtUnixUnix timestamp the multisig finalized the release.
authorSiged25519(releaseHash) by a quorum member. The signature you verify.
quorumPolicy{threshold, memberCount, multisigPda} — the rule that was in force at signing time.

Verify with the CLI

The reference verifier is melusina-pearl-tool. Build from hrbrlife/melusina-attestdeployer-tool or grab a release binary, then:

# Pull the app's RELEASE.json + the .spk
curl -sLO https://hrbrlife.github.io/melusina-static_store/attest/<appId>/RELEASE.json
curl -sLO https://hrbrlife.github.io/melusina-static_store/packages/<packageId>.spk

# Save the matching metadata.json from /signatures/<appId>/metadata.json
curl -sLO https://hrbrlife.github.io/melusina-static_store/signatures/<appId>/metadata.json

# Verify against the on-chain ReleaseEntry
melusina-pearl-tool verify-release \
  --spk <packageId>.spk \
  --metadata metadata.json \
  --release-json RELEASE.json \
  --app-slug <app-slug>

Exit 0 = the .spk byte-matches appHash, the releaseHash reproduces from canonical inputs, the authorSig verifies under a current quorum member's pubkey, and the on-chain releaseEntryPda account agrees with all of the above.

Offline mode: set MELUSINA_ATTEST_OFFLINE=1 to skip the on-chain RPC lookup and only validate the local schema + the ed25519 signature. Use this when you have an air-gapped quorum-member pubkey list and don't want to leak the install attempt to a public RPC.

Verifying without the CLI

Everything here is plain ed25519 + SHA-256 + Solana account reads. A custom verifier in any language only needs: (1) a Solana RPC client to read releaseEntryPda, (2) ed25519 to check authorSig against releaseHash, (3) SHA-256 to recompute appHash from the .spk. The catalog gives you the inputs; the chain is the oracle.
